---
description: This plugin coaches you to reach the team goal in the most efficient way. It analyzes your workflows and aligns them to team goals.
argument-hint: "<invite code from your manager, e.g. K7QP-3FXA>"
---

Set up Yolk on this Mac. These are the approval moments (step 1; step 4.4 for the profile; step 4b for a manager).

1. **Say what the user approves, then ask for explicit confirmation.** Be transparent: this answers work-monitoring questions from the manager's AI about how the user worked.
   - Yolk reads Claude Code sessions (`~/.claude/projects`), Screen Time, git, any cloud connectors already set up, and browser history (domains, page titles, timing) from Chrome, Arc, Brave, Edge, Chromium and Vivaldi. Questions can be about any past day the manager picks, including days before setup; the last 7 days are also summarized automatically.
   - **After this approval a background job answers the manager's check-ins automatically.** The user does not review each answer before it is sent; every answer sent is kept in `~/.claude/yolk/audit/` (`<id>.sent.json`) to read afterwards.
   - **Only sanitized answers to the questions from the manager's AI, and the work profile the user approves (next point), leave this Mac**, over HTTPS to the Yolk server. The answers are at business level (meeting subjects, document titles, client names). The agent is instructed never to include raw code or file contents, verbatim prompts or chats, email or message bodies, full URLs or secrets; it may paraphrase, judge how the user works with AI, and name work pages by title or domain. A deterministic filter also removes code blocks and secret-shaped strings before anything is sent. Personal activity is reported only as a total.
   - **Setup drafts a work profile of the user** from their recent Claude Code sessions (or from what they paste or answer). Only the profile the user approves is sent to the Yolk server (step 4.4); it replaces the current profile (at first, the one the manager wrote), and the Manager AI and the manager see it.
   - **Raw activity data and daily reports stay on this Mac.** They are never sent to Yolk or the manager; Claude processes them under the user's own account (Opus 5.5, no API key). Each finished day becomes a private summary in `~/.claude/yolk/days/`, which the agent uses to answer the questions. Raw data is deleted after 14 days.
   - The Manager AI also writes a daily report on the user from these answers; the manager can read it on the server and through a manager's plugin. The manager sees the questions, the sanitized answers, the same coach brief the user gets (with its verdict on each part of the day), when each answer arrived and when this device last checked in, and a team digest the user never sees. The user sees their own daily report (`/yolk:report`) and a coach brief built from their answers (`/yolk:brief`). The device token can only read the user's own questions and briefs. An employee's plugin contains no manager logic; a plugin claimed with a manager invite code also has a manager role (step 4b).
   - The background job runs on this Mac at every login, right after the Mac wakes, and every 2 minutes, to do all of the above. `/yolk:leave` removes it.
2. **Invite code:** use `$ARGUMENTS`, else ask for the code the manager sent (not a link).
3. **Link:** `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/employee_runner.py" claim "<invite code>"`. Never read, print or `cat` `~/.claude/yolk/agent.json` (it holds the device token). If the invite is "not valid" or "already used or expired", tell the user to ask their manager for a new one and stop.
4. **The user's work profile** (after the claim, which gives the device token; before 4b). The Manager AI calibrates to it.
   - **4.1** Run `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/employee_runner.py" profile-sources`. It prints JSON, and sends nothing: the user's Claude Code projects of the last 30 days, newest first (path, session count, last active date, up to 5 sanitized first-prompt excerpts each), the total `sessions`, and `thin` (fewer than 10 sessions).
   - **4.2** Draft the profile from that digest only, in these sections: **Role and responsibilities**, **Current projects**, **Tools and ways of working**, **Handles** (GitHub login, Slack name, Linear email). Business level only: no code, secrets, URLs, backticks, quoted lines, or lines starting with `$` or `>`. Up to about 2000 characters. Never invent: write "unknown" in a section rather than guess.
   - **4.3** If `thin` is true, give the user this prompt to send in Claude chat or Cowork, and ask them to paste the answer back: "Write a short work profile of me from what you know from our past conversations: my role and responsibilities, the projects I work on now, the tools I use, and my GitHub, Slack and Linear handles. Plain text, no links." Add what it says to the draft. Then ask the user for what is still unknown (asking is not inventing): any unknown handle (GitHub login, Slack name, Linear email), whether or not `thin` is true; and, if `thin` is true, role and responsibilities and current projects too.
   - **4.4** Write the draft to `~/.claude/yolk/profile-draft.md`. Show the current `~/.claude/yolk/profile.md` (the current profile on the server, saved by the claim: the manager's, or the user's own from an earlier setup; it may be empty), then the draft in full, and say that the draft replaces it, so the user can carry over anything worth keeping (handles, for example). Ask the user to approve the draft or say what to change. Only after explicit approval, run `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/employee_runner.py" profile ~/.claude/yolk/profile-draft.md`. It prints `{"status": "sent"}` (the profile is now `~/.claude/yolk/profile.md`), or `{"status": "rejected", "reason": ...}` (the server's checks or the privacy filter refused it): then fix the draft for that reason, show it again and ask again. If it fails any other way (an HTTP error, the server cannot be reached), tell the user and go on with setup: the current profile stays. Delete the draft afterwards in every case.
   - **4.5** If the user declines, skip this step (and delete any draft): the current profile stays.
4b. **Manager role: second consent, before anything is scheduled.** The role is known only after the claim: read it from the line the claim in step 3 printed ("Linked to ... role employee|manager"). If it is `employee`, skip this step. If it is `manager`, tell the user and ask for explicit confirmation:
   - Once per day this plugin reads the manager's own connected systems (Linear, GitHub, public Slack search, team meetings, planning docs, Notion, Drive, monday boards, CRM/HubSpot), **read-only** (no built-in tools, only read-only connector tools), to collect company goals and what each employee worked on that day.
   - Only business-level facts with their sources, and the company goals, are sent to the Yolk server. No DMs, private channels, 1:1 meetings, board or investor material, HR material or individual deal amounts are to be used, and nobody is quoted.
   - The manager can read each team member's daily report with `/yolk:report <employee>`.
   - Employees can read the check-in questions that the Manager AI generates from these facts.
   - The manager can switch the automatic collection off with `/yolk:context manual`, and then post a date's context from their own markdown file with `/yolk:context <date> <file>` (no connectors are used for that).
   - Everything sent is kept in `~/.claude/yolk/audit/context-*` (`.raw.json` before the privacy filter, `.sent.json` as sent).
   If the user agrees, run `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/employee_runner.py" manager-consent` (until then the plugin does not collect). If the user declines, run `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/employee_runner.py" leave` and stop: nothing is installed.
5. **Check `python3 --version` and `claude --version`;** help install the Claude Code CLI if it is missing.
6. **Full Disk Access (only Screen Time needs it; the rest works without):** before the background job starts, since its first run builds yesterday's report at once. macOS never asks for it and the plugin cannot request it. Grant it only to the path `bash "${CLAUDE_PLUGIN_ROOT}/scripts/install_schedule.sh" --fda-path` prints, usually Apple's `Python.app` (it shows as "Python" in the list; the terminal and the Claude Code app need it only for a `summarize` the user runs themselves): run `open "x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles"`, then "+", Cmd+Shift+G, paste the path, Open, turn it on. Wait until the user says it is on, or that they skip it (Screen Time is optional), before step 7.
7. **Start the background job:** `bash "${CLAUDE_PLUGIN_ROOT}/scripts/install_schedule.sh"`. It starts at once; the first run builds yesterday's report and answers the check-in the server may have opened.
8. **Auto-update, once:** `/plugin` → Marketplaces → `avaturn` (`yolk` if it was added before the rename) → Enable auto-update (skip if the organization manages it).
9. Run `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/employee_runner.py" status --wait 1800` with the Bash tool's `run_in_background`; do not poll it. Tell the user the session will say when the first report (and the brief, usually within 20-40 minutes) is ready; then point to `/yolk:report <date>` for each date in `reports_ready`, and `/yolk:brief` if a brief arrived. Progress: `~/.claude/yolk/audit/agent.log`.
